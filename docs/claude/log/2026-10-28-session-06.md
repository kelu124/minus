## Datasheet reading (DS70005592)
- DMA (Table 16-1): one module, 6 channels, clock = **standard-speed peripheral clock** (= CPU/2, §15:
  fast = CPU, standard = /2, slow = /4). §16.2: "when the CPU and DMA access the SFR simultaneously
  the CPU gets priority and the DMA waits". Single DMA data bus (§16.4). `BMXINITPR.DMAPR` can raise
  the DMA's *RAM* priority above the CPU (§7.3.1).
- ADC (§18): 2 cores, 20 channels, "fast" bus, TAD = CLKGEN6/4 = 80 MHz, conversion 1.5 TAD, sampling
  0.5 + 2n TAD (SAMC). Modes: single, window, **integration** (CNT samples summed, back-to-back
  re-trigger TRG2SRC = 2), **oversampling** (4/16/64/256, ACCBRST burst). Repeat timer trigger
  (TRG1SRC 3, RPTCNT ADC clocks). Each channel: own 32-bit DATA register (0x818, 0x830, … not adjacent).
- Op amp (§32): 3 instances, 100 MHz GBW in high-power mode, `AMPxCON1` = AMPEN/HPEN/UGE/DIFFCON/OMONEN.
  OA1OUT is a real pin (RA2 = AD1AN0), OA1IN+ = RA4 = AD1AN1, OA1IN- = RA3.

## Implemented (rp 0.1.19 → 0.1.26, pic 0.1.8 → 0.1.18, proto 4)
- `ACQ [div [samc [in [navg]]]]`: `in` = ADC1 PINSEL (9 node, 0 OA1OUT, 1 OA1IN+), `navg` = integration
  mode N back-to-back conversions summed. Op amp 1 enabled at boot (AMPEN + HPEN, external gain);
  `AMP1 0|1` on the link. RP `acq` passes the arguments through and names the input in the header.
- `ADCBB n [ovs]`: DMA-free ADC throughput test (software trigger, n back-to-back conversions, Timer1).
- `ACQCPU trg [rptcnt [gap [phase]]]` / RP `acqcpu`: CPU-loop reader into `acq_buf`, same reply as ACQ.
- Bus-quiet DMA wait loop (poll `DMA0STAT` once per 1024 NOPs, iteration-count deadline, Timer1 read
  only at the end). Default `ACQ_TRIG_DIV` 4 → **8**.
- Flash cycle used all session: build PIC → build RP (embeds hex) → `reboot dfu` + copy UF2 →

## Measurements (all board 2, RP-crystal `rp_fill` agrees with the PIC's Timer1 within 1 %)
1. **First OA1 capture** (`acq 8 0 0`): OA1OUT = 4057 LSB = **3.27 V** flat (σ 1.2). `acq 8 0 1`: RX node =
   740 LSB = **0.596 V** (the D7 clamp). `acq 8 0 9`: node 1326 LSB = 1.07 V after the usual ~60-sample
   settling ramp from 2017. With `AMP1 0`, OA1OUT reads 34 LSB = 0.03 V → the op amp drives the pin and
   is saturated (0.6 V × 11 > rail), exactly the half-wave/bias problem predicted in session 05.
2. **Rate anomaly:** the untouched DMA path now gave 23.3 Msps at div 4 *and* div 8 (last session 26.6),
   and 19.98 on the first run — only the code layout had changed. Hypothesis: the tight poll loop
   (`while (!DONE && TMR1 < deadline)`) competes with the DMA on the SFR bus.
3. **Quiet loop (64 NOPs/poll):** div 16 → 97.5 ns, div 32 → 195 ns (nominal 100 / 200 ns!), div 4 → 50 ns.
   So with the CPU quiet the period is `div × 6.25 ns` and the old numbers (div 16 → 75 ns, div 32 →
   120 ns, i.e. *more transfers than triggers*) were **duplicated samples**. Proof in the data: the tight
   poll capture repeats a value every 7–8 samples in the steep settling ramp (1819 1819, 1622 1622,
   1504 1504 …), the quiet capture shows the same per-step decrement with no repeats.
4. **Quiet loop (1024 NOPs/poll), DMAPR 0 and 1 identical:** div 4 → 50.3 ns, 5 → 62.8, 6 → 75.4, 7 → 59.7
   (jitter), 8 → 50.3, 16 → 100.5 ns. ⇒ **DMA floor = 50 ns = 8 CPU / 4 standard-bus clocks → 20 Msps**;
   below that every other trigger is silently ignored (no overrun flag).
5. **Integration mode:** `acq 8 0 0 2` → values 8110 (= 2 × 4057, 13-bit sum), node ramp 3999 → 3111;
   but period 88 ns at div 8 (nominal 50), div 4 → 85 ns, div 16 navg 4 → 201 ns ⇒ each triggered
   sequence costs ≈ 25·N + 40 ns.
6. **ADC core alone:** `ADCBB 4095` → 1026 ticks = 102.6 µs = **25.05 ns per conversion**; oversampling
   burst 256 → 6.6 µs. The 40 Msps spec is real for a single channel.
7. **CPU loop:** 4095 reads in exactly 102.4–102.5 µs = **4 cycles per read**. With trigger sources 2
   (back-to-back) and 3 (repeat timer, RPTCNT set before ON, CH1 software kick tried) the data is a
   constant stale value — they do not fire in single-sample mode. With the SCCP trigger (trg 12):
   div 8 → every ramp value exactly twice (2014 2014 1961 1961 …), div 8 + 4 NOPs (50 ns reads) → every
   value once, i.e. a clean 20 Msps capture without DMA; div 4 (25 ns) → first runs all-distinct ramp
   (one duplicate in 40), later runs on the next build → solid pairs. Phase sweep (NOPs before the
   loop, pic 0.1.18): phases 0, 1, 5 → 7–9 duplicate pairs per 80 ramp samples; phases 2, 3, 4, 6, 7 →
   every value twice. ⇒ the 25 ns CPU read collides with the ADC's result write (CPU wins the bus);
   marginal at 160 MHz.

## Answers to the two questions
- **Why a 40 Msps ADC when the DMA cannot follow?** The ADC is built for 20 multiplexed channels,
  hardware oversampling/integration and low-latency control loops; the result path to RAM (DMA on
  the half-speed bus, 50 ns per word) was never meant to stream one channel at 40 M words/s. The core
  itself does 25 ns per conversion.
- **How to get 40 Msps?** (a) `acqcpu` CPU loop at 160 MHz — works at 50 ns, marginal at 25 ns;
  (b) CPU at 200 MHz (5-cycle loop with slack, DMA to 25 Msps; needs PLL2 for the 320 MHz ADC clock);
  (c) `navg` sums at div ≥ 15 (40 Msps inside each burst, 10.7 M results/s). Default stays 20 Msps DMA.
