## Task: study kiffie/pic32probe + pic32prog-kvh (RP programming a PIC32)
- Cloned both into `pic32prog/` (added as git submodules: pic32probe master @ 5a03cf2,
  pic32prog-kvh branch `pic32probe` @ 93805d6). Read `probe.rs` (PIO 4-phase ICSP),

  `adapter-pic32probe.c`, `pic32.h`, `adapter-bitbang.c` + `ICSP_v1E.ino`, and `target.c`.
- **Finding:** pic32probe is an **EJTAG-over-2-wire** dongle for MIPS-core PIC32 (MX/MM/MK/MZ):
  JTAG TAP instructions, MTAP commands, EJTAG serial execution, Programming Executive. Our
  PIC32AK1216GC41048 is a **dsPIC33A core** with the dsPIC-style ICSP (2-bit command + 32-bit
  opcode, VISI/NVMCON) that `pic_icsp.c` already transcribes from DS70005583. `pic32prog` has no
  dsPIC/33A/32AK device entry. → logical layer: not applicable; physical/entry layer: comparable.
- Cross-checked the entry sequence bit-for-bit: MIPS key 0x4D434850 MSB-first and our
  0x8A12C2B2 LSB-first both emit "MCH" + one byte ("MCHP" vs "MCHQ"), so our LSB-first emission
  is right. MCLR handling (push-pull during session, Hi-Z + board pull-up idle, low ≥1 ms to
  exit) is the same pattern. pic32probe clocks the key at 100 kHz and the data at 1 MHz via PIO;
  we bit-bang both at ~1.2 MHz → queued "slow the key / `pic speed` knob" as the first thing to
  try if `pic id` still fails once MCLR is verified low.
- Architecture note: pic32probe = dumb dongle + smart host (hex, device table, PE on the PC);
  ours = self-contained (hex embedded in the RP image). Optional later: `pic raw` streaming from
  `tools/rpcli.py`, like pic32prog's ASCII `adapter-bitbang` dongle.
- Wrote `pic32prog/README.md` (study + applicability table), memory 0010, TODO items, DONE
