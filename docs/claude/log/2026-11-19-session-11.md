- Pulser topology (netlist): GPIO8 "PWM_H" → U3 IN A → OUT A → R5 10 Ω → **Q2 IRLML6244 N-FET to GND**; GPIO9 "PWM_L" →

  → TODO_HARDWARE pull-up. Until fw 0.1.30 nothing drove GPIO8/9 on this board, so `Transducer` sat at +5 V DC.
- RP 0.1.30: `firmware/rp2354/pulser.pio` (pio1 SM0, set pins GPIO8/9, in pin GPIO7 = RDY). One FIFO word per shot:
  fire-now bit, hi (12 b), dead (7 b), lo (12 b); phases hi+2 / dead+4 / lo+2 cycles at 150 MHz. Waits RDY low then rising.
  `pulse` = shot now; `pe [hi [lo [in [dead]]]]` = arm, send `ACQ 4 0 <in> 1`, report fired, disarm (SM restart + idle pins).
  `pulser_init()` is the first call in `main()`.
- PIC 0.1.22: input codes 16..31 = ADC2 (`acq_run_adc2`: AD2CH0 TRG1SRC 12, DMA0 CHSEL 0x40 "ADC2 – AN0" from DS70005592
  Table 16-2; ADC1 CH0 idled for the run); both cores on CLKGEN6 (Table 18-1). Default input 25 = AD2AN9. AMP2 on at boot.
  Proto 7 on both sides. Built with XC-DSC 3.31.01, flashed via `pic flash` (verify ok, 3928 words).
- Bench: `pulse` → fired, 200.0 / 26.7 / 500.0 ns. `pe` 12/12 runs at 24.86 Msps after the first; the first capture after an
  input change came back twice at 18.08 Msps (fill 226 µs, status ok) — same symptom as the open "intermittent slow acq".
